# API 与错误责任

请求进入已有 api/http/service 层，复用认证、超时、响应解构和错误码映射，不在页面复制请求客户端或认证头。

查证请求层的错误行为：是否 reject、是否已经提示、是否返回业务失败对象。业务层按真实契约处理成功与失败；统一错误提示已存在时不再重复 `message.error`，表单校验或前端业务校验仍可独立提示。

无论错误由谁展示，都要结束 loading/submitting，避免失败仍显示成功、失败清空输入、未处理的 Promise。必要时保留失败状态与重试入口；不能将「不重复提示」理解为「忽略异常」。

## 调用与契约检查

分页字段、响应解构和成功条件按现有接口；页面不重复包装请求客户端。失败路径恢复 submitting，查询竞态按 [状态规则](state.md) 处理。请求类型按 [类型规则](types.md)，命名按 [命名规则](naming.md)。

第三方 SDK 按项目现有适配层封装，统一认证、类型与错误责任；不要把 SDK 原始结构扩散到页面。分页字段、响应成功码、状态枚举均按真实协议，不能强制改成 page/list/200 或禁止合法的状态 0。

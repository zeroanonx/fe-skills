# 新建文件与目录规则

新增文件、移动文件或拆分模块前读取。用户明确要求与目标项目配置优先。新项目或无明确目录约定时采用 [最小项目结构](project-structure.md)，已有项目保持真实分层。

## 新建前判断

1. 搜索同名/同职责模块及调用方，确认现有文件是否可兼容扩展。
2. 看同目录 2～3 个实例，核实大小写、入口文件、配套样式、类型和测试命名。
3. 确认文件职责及使用范围：单页私有、业务共享或跨业务通用。
4. 在既有层级选择位置；只有现有结构确实无法容纳且任务需要时才新增目录，不顺手建立 services/common/helpers 等平行体系。

## 放置决策

| 内容 | 优先位置 | 新建时检查 |
| --- | --- | --- |
| 页面入口 | 基线为 views/PascalCase/index.vue，已有项目沿用既有位置 | 路由注册、权限、菜单与懒加载 |
| 单页子组件 | 当前页面的 components 或项目同类位置 | 不暴露到无关全局入口 |
| 共享组件 | components 按职责分层 | props、兼容性、真实复用场景 |
| 请求与类型 | 既有 api/http/service、types/interfaces | 认证、错误映射、输入输出类型 |
| 局部 hook/composable | 当前业务模块 | 不因 use 前缀自动提升公共层 |
| 常量/工具 | 私有留页面；全局 constants/modules、shared/utils/modules 与 index.ts | 业务归属和重复定义 |
| 样式/测试/素材 | 项目已有邻接或集中模式 | 引用路径、构建规则与检查脚本 |

## 文件内容与注册

- 只创建本次确有职责的文件，不先建空 Loader、store、types、README 占位。
- 文件头用途注释按项目习惯添加；公开函数、类型、副作用按 [注释规则](comments.md) 说明。
- 依次组织 import、类型/常量、状态与业务分区、导出，实际顺序以项目为准。
- 使用既有别名与扩展名约定；仅当项目采用 barrel 时更新 index，避免公共索引反向导入子模块造成循环。
- 同步必要的路由/组件入口、类型导出、测试引用和文档链接；没有使用方的无用文件不交付。
- 移动/重命名后查全量引用、大小写敏感路径、动态 import 和构建配置；macOS 可用的大小写错配也可能在 CI 失败。
- 不覆盖同名已有文件或顺手移动用户未提交改动；合并前先读原内容。

交付检查：文件位置有参照、命名一致、无空壳、引用有效、必要检查通过。

采用团队基线时，hooks/stores/types 也按 modules + index.ts 分类导出；页面私有常量 constans.ts、表格列 columns.ts 不提升到公共层。全局样式入口为 assets/styles/index.css，图片/图标放 assets/images、assets/icons。

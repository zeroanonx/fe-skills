# 类型与数据边界

TS 项目沿用其严格程度与类型目录；JS 项目不因本技能擅自迁移技术栈。

- Props、事件参数、请求 Params/Body/Response、公开函数返回值与共享状态定义清楚；复用已有模型，不复制近似类型。
- 接口可空、可选、分页和枚举按真实契约表达，不为了方便把所有字段设为可选。
- 外部不确定数据使用 unknown 并收窄/校验，不能仅 as 成业务类型就假定安全。
- 避免无理由 any、非空断言、ts-ignore；必要兼容边界限制范围并说明原因与后续处理。
- 区分 null、undefined、空字符串、0 和 false，默认值不能吞掉有效值。
- 导出使用 type-only import 等写法以项目编译配置为准；运行时枚举与纯类型不能混淆。
- 泛型只解决实际复用问题，不为单一接口建立复杂类型框架。

关键类型变更查调用方与序列化；类型检查通过不证明接口运行数据符合声明，契约不确定时说明限制。

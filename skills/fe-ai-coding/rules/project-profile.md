# 项目规范识别

编码前按改动范围识别项目；用户要求熟悉全库或生成长期规则时扩大扫描。记录配置、真实代码与团队文档的来源，不能把技能默认建议当项目既有事实。

| 证据 | 提取内容 |
| --- | --- |
| package.json、锁文件 | 技术栈、版本、包管理器、真实脚本与已有依赖 |
| README、适用项目指令 | 启动方式、目录职责、业务约束、门禁 |
| 构建、TS、Lint、格式化、样式配置 | 别名、严格程度、属性顺序、允许语法、输出边界 |
| 路由、组件、API、store 的抽样代码 | 命名、通信、封装、异常与副作用处理 |
| 相邻测试、素材、主题与文案 | 验证方式、设计 token、资源与 i18n 来源 |

每个相关模块读 2～3 个代表文件，规模小按实际数量；忽略 node_modules、dist、.git 和生成目录。无法判断的职责标待确认。

输出目录树时标注用途，只列与任务有关的核心层级，说明省略范围；新项目按 [最小项目结构](project-structure.md) 描述，不伪装成已存在的目录。

局部画像需覆盖：包管理器、职责分层、命名/导入、组件/请求/状态模式、文案/主题、校验脚本。大改动在对话中简述主要约定；纯局部改动无需额外写报告。

当前环境有适用 Vue/React/TypeScript 技能时按任务加载，其建议服从项目事实和用户要求；不假定固定安装路径，不因为可选技能未安装阻塞正常扫描。

# 校验与交付

先确认项目真实脚本和适用门禁，不猜测命令。每项结果区分已通过、失败、未运行；失败说明与本次改动的关系。

| 改动 | 最小相关校验 |
| --- | --- |
| 新建/重命名文件 | 路径、引用、导出、大小写及相关类型/Lint |
| TS 业务逻辑 | 类型检查、Lint，关键逻辑测试 |
| API/并发/状态缺陷 | 成功、失败、空数据、恢复与关键竞态测试 |
| CSS/主题 | 已有样式 Lint，真实渲染和受影响主题/视口 |
| 路由/加载边界 | 注册、直达、跳转、权限与必要构建 |
| 纯注释 | 注释准确、分区成对、无意外代码改动；项目要求的检查 |

无测试基础时不引入整套框架，按风险执行可用验证并说明缺口。纯注释、低影响可逆样式修改不为形式增加测试。不要重复运行已通过且未受后续改动影响的检查。

涉及 UI 需区分类型/Lint/构建与浏览器实际验收；设计还原可配合 fe-ui-verification 的 HTML/MD 报告。fe-ai-coding 本身默认交付代码和对话摘要，不额外生成代码规范报告。

交付包含改动文件、行为、必要注释/测试、实际命令与结果、未验证范围、缺失素材/接口/mock。不能因为命令不可用就宣称通过。

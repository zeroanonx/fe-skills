# 生成或完善项目 AI 规则

仅当用户明确要求生成/完善长期项目规则时执行。普通代码修改只读取规范，不自动改写规则文件。

## 1. 收集事实

按 [项目画像](project-profile.md) 扫描，结合本技能相关细则整理技术栈、目录树、命名、组件、API、状态、注释、样式和真实校验脚本。

项目配置与重复实现优先，文档有过时内容时标明冲突。证据不足的技能默认建议标「建议/待确认」，不写成强制项目事实。不复制全部细则或第三方教程。

## 2. 确定输出工具

用户已指定工具或文件时直接沿用；未指定且现有规则明确服务某工具时沿用并说明；仍无法确定时询问 Cursor / Codex / Claude，继续整理事实，未确定前不写最终规则文件。

| 工具 | 默认产出 |
| --- | --- |
| Cursor | .cursor/rules/*.mdc |
| Codex | 项目根目录 AGENTS.md，按需遵从已有嵌套指令布局 |
| Claude | 项目根目录 CLAUDE.md |

## 3. 提炼可执行规则

涵盖项目概述、带职责的文件树、目录/命名、组件通信、API/路由/状态、样式/主题、注释、AI 工作方式和门禁命令。新增项目采用 [最小结构](project-structure.md)，既有项目记录真实结构。

样式规则写真实校验命令、修改范围、需要遵守的关键规则；不复制整个 Stylelint 配置。项目没有脚本时说明，不虚构 pnpm lint:style。

Cursor 小项目可合为 project-conventions.mdc，大项目按职责拆文件。命名 kebab-case，globs 限定对应文件，只有全局规则用 **/*；alwaysApply 只用于必须始终加载的内容。

```yaml
---
description: 项目样式约定
globs:
  - "**/*.{css,less,scss,vue}"
alwaysApply: false
---
```

Codex/Claude 使用相同项目事实写 Markdown，不生成未选择工具的配置。

## 4. 写入与交付

先读已有目标文件。没有则创建；已有则合并缺失条目，保留用户内容；冲突且会改变规则含义时展示具体差异，等待用户取舍，不整文件覆盖。用户明确授权的替换范围可执行，不重复询问。

校验相对链接、真实路径、glob 范围、格式和命令是否存在。交付技术栈、包管理器、带用途的目录树、证据来源、生成/更新文件链接、门禁摘要和未确认项。

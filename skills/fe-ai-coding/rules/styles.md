# 样式、主题与素材

## 配置优先

修改 CSS / Less / SCSS / Vue style 前，检查 `package.json` 样式脚本、Stylelint/CSSLint、PostCSS、格式化配置和同目录样式。属性顺序、选择器命名、嵌套、单位、作用域与变量用法遵从目标项目。

保留既有 scoped、CSS Modules、全局入口或工具类体系；动态 class 复用既有方案，不强制 SCSS Modules 或 classnames。不为排序重排整份旧样式。

## 设计值与主题

- 颜色、字体、间距、圆角、阴影和层级优先使用已有 token、变量或 mixin；核实变量存在，不照抄 `--ant-*`、`--shentu-*` 等特定前缀
- 有设计稿时记录设计值与项目 token 的对应关系；不一致时明确差异，不能随手用近似 token 宣称精确还原
- 新 token 沿用现有主题入口；主题相关改动检查项目支持的浅/暗色及交互状态，避免局部硬编码破坏主题
- 分别识别 fill、stroke、文字颜色、透明度、shadow、blur 与圆角；颜色 alpha 不与容器 opacity 混淆
- 布局取决于设计与响应式要求：限宽、固定列、滚动、卡片半露都可能合理，不一律改成满宽或隐藏溢出

## 素材与占位

先找现有图标库、iconfont、SVG、图片资产。资源缺失时保留设计尺寸与比例，遵从项目占位组件/样式并标注 TODO 替换点，不凭空引用不存在的素材或外部占位服务。

只有项目明确禁止临时 SVG 时才遵守该限制；已有合法 SVG 素材可正常复用。占位用于表达缺失，不应伪装成最终素材。交付列出未替换资源及影响，图片加载失败与素材未提供分别处理。

## 渲染校验

以浏览器实际效果确认按钮尺寸、对齐、字体、裁切、弹层和响应式；样式源码与编译成功不等于视觉通过。遇到覆盖先检查生效样式与层叠来源，CSS Modules 也可能在同一元素上被其他规则覆盖，不盲目提高选择器权重。

## 全局与局部样式

团队结构下，全局通用样式、主题及已有 tw 入口位于 assets/styles，index.css 为入口；组件/页面样式留在局部作用域。LESS/SCSS 导入、变量与规则按配置顺序组织，避免过深嵌套；可拆为语义类，不能为了压层数引入选择器污染。新样式的属性顺序、简写、单位和颜色格式由 Stylelint/Formatter 决定。

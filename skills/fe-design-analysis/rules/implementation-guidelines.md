# 设计还原实现建议

提出实现建议时读取；本技能仍只交付分析，不直接修改业务代码。建议要引用区域 ID 与设计证据。

## 容器与响应式

先辨认流式内容、限宽居中、固定侧栏和主内容自适应。记录内容区与画板两侧距离，而不是将画板绝对坐标直接写成 CSS。设计为限宽居中时 max-width 合理；设计要求铺满时再排查多余限宽。单张桌面稿不能证明移动端断点。

## 列表与布局选择

明确列数是固定、随宽度变化还是横向滚动，记录最小卡片宽、gap、末行策略。跨行等宽可选 Grid；每行独立分配可选 Flex。以下仅展示语法，值需来自设计：

```css
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(100%, 280px), 1fr));
  gap: 16px;
}
.flex {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}
.flex-item {
  flex: 1 1 280px;
  min-width: 0;
}
```

Flex 的 basis 不是最小宽度；需要最小约束时单独定义。Grid 的 minmax 不能用在 flex 简写中。父级宽度已由正常文档流确定时无需额外 width。

## 完整性与对齐

必要文字和操作不得无意裁切；设计允许的省略、横向滚动半露卡片应保留。不要 slice 数据或 overflow hidden 来掩盖布局错误。图标与单行文字可居中，多行文字可能顶端或基线对齐；确认 flex-direction，align-items 控制交叉轴。

## 样式与素材

复用项目 token/组件，记录设计值与 token 差异。背景透明度、阴影、毛玻璃、圆角分别提取。缺失图片或图标列出尺寸、位置、比例和替换点，不把占位当最终素材。

CSS Modules 仅隔离类名，无法保证同一元素上的规则不互相覆盖。实现后应在浏览器检查按钮尺寸、对齐、指定交互状态与视口；设计分析本身不代表这些检查已完成。

# Fe Project Migration

把旧前端业务迁入新项目，承接完整操作链路，适配目标工程的结构、请求、组件和运行环境。

## 怎么用

安装见[仓库 README](../../README.md)，安装或更新后重新开启 Agent 会话。

```text
/fe-project-migration 只读梳理旧项目 /path/legacy 的订单模块，对照 /path/target 输出迁移缺口
/fe-project-migration 为旧项目订单模块制定迁移方案，暂不修改业务代码
/fe-project-migration 将 /path/legacy 的订单链路迁到 /path/target，保持已确认接口语义，按目标项目规范实现并验收
```

Codex 可用 `$fe-project-migration`。提供两端项目位置、迁移业务、用户最终动作、可修改范围和已知约束；已有上下文可直接沿用。可以指定分支或参照提交、需求与截图、测试账号和目标容器。凭证通过项目现有安全方式使用，不写入报告。

## 产出

```text
{目标项目}/fe-spec/project-migration/{模块}/{run-id}/
├── migration.md
├── migration.html   # 主动打开并检查渲染
├── evidence/        # 真实证据，按需
└── handoff.md       # 长任务交接，按需
```

报告包含版本基线、业务地图、旧新落点、保留与适配决策、待确认项、批次和场景证据。执行模式还交付目标项目代码与必要测试；只读分析和方案模式不修改业务代码。已有 OpenSpec 等规格直接复用并在报告中链接。

## 重点检查

- 展示值、判断值、提交值与最终载荷是否一致；全选、空值、分页语义以当前业务契约为准。
- 角色、状态、返回、失败恢复和共享数据消费方是否遗漏。
- 旧缓存、深链与原生容器存在时，是否有实际兼容检查。
- 对照目标同类页面，避免为了形式拆文件或复制旧工程结构。
- 按证据分别记录实现、验证、构建与发布，环境受阻不算通过。

不默认改后端、删除旧项目、发布或切流；依赖及公共配置变更按本次授权与项目约束处理。详细流程见 [SKILL.md](SKILL.md)。

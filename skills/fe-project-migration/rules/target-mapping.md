# 目标工程映射

本文件用于阶段 2，前提是阶段 1 完整盘点已通过。逐项关联迁移项 ID，不能只映射准备先做的页面；所有本次项都有处理决定后才能进入阶段 3。

读取目标项目真实配置、目录及至少一个可用的同类页面，优先复用已有路由、请求封装、类型、表单校验、组件、反馈、状态和布局能力。没有同类实现时说明依据缺口，给出符合当前配置的方案。

逐项写「旧端位置与职责 → 业务不变项 → 目标落点/复用能力 → 工程适配 → 影响与验证」。决策使用：保留、适配、替代、经确认删除、待确认。只有迁移范围内且已经明确淘汰的能力才能删除；默认不修改旧端文件。

## 目录与抽象

- 目标项目已有目录及命名优先。新建 Vue 工程且明确采用团队结构时，可使用 `fe-ai-coding` 的最小分层；其他技术栈遵循自身项目约定。
- 全局共享与页面私有分开；常量、类型、hooks、utils 有实际跨模块复用时进入公共层。请求层与独立业务职责可单独组织，不为减少文件数挤进一个大文件。
- 只在单页使用的简单文案、正则和函数不为形式统一外提。旧模块文件拆分不必原样搬运，也不能把职责遗漏当作收敛。
- 记录新增、移动、替代文件的职责、命名、导入路径和调用方；检查大小写敏感环境、别名、循环依赖与导出边界。

## 框架与运行差异

核对生命周期与清理、响应式状态、路由传参/返回、表单值与校验时机、事件绑定、列表键、请求取消、缓存策略和样式作用域。只迁移与本次业务有关的机制，不整库升级。

布局先明确高度承载层、内容滚动层、头底栏与安全区归属，再选择 CSS 方案。fixed/absolute 是可用实现，需要解释容器关系并验证长短内容；不能凭静态截图删掉旧容器适配。

依赖、公共请求、构建配置和后端协议是否可改，以用户授权及项目规则为准。先用已有能力解决；确需超出范围时提交具体阻碍、方案与影响，取得对应决定，独立批次继续。不得照搬历史案例中的固定禁止项或依赖版本。

# 还原业务链路

本文件用于阶段 1。按 [完整迁移盘点](task-inventory.md) 展示并落盘全部页面、接口、函数功能、样式等迁移项；只有业务描述而没有清单不能通过门禁。

从一个真实用户动作开始阅读：入口 → 路由/页面 → 事件 → 状态变化 → 请求转换 → 最终载荷 → 响应处理 → 后续页面。覆盖关联子页、弹窗和其他入口，不能只统计页面数量。

每条链路记录入口、角色/状态、动作、页面职责、状态前后、数据来源、接口与提交值、成功/失败后续、依据、待确认项。读调用点和条件分支；函数名和 service 清单不能证明行为。

## 参数与状态追踪

- 区分展示名称、判断值和提交 ID；追踪默认值、类型转换、序列化、空值过滤与重置。
- 将接口地址/方法、认证上下文、关键字段、分页/排序、响应消费、错误处理与目标映射关联。传输封装变更不等于允许业务协议变化。
- “全部”“未选择”“当前页”“搜索结果”分别确认集合来源和提交语义。空数组、空字符串、缺字段与特殊标记按真实契约解释，不套用某个案例。
- 查看按钮显隐以外的权限检查、路由入口、请求范围和服务端约束；检查多个角色、实体状态及跨页面状态。
- 记录 loading、防重复提交、并发结果、取消/返回、失败后输入保留与重试，按实际存在的行为选择检查项。

涉及共享数据时同时查生产方、转换点、消费方、持久化与清理时机，按 [兼容性规则](compatibility.md) 检查历史影响。

如果说不清最终请求、角色实际控制条件或数据返回后的消费方，继续针对缺口检索，不能将该部分标为已理解。无法访问的接口、历史版本与运行环境单独记录；其余有依据的链路继续推进。

# 验收与诊断

本文件用于阶段 4 的局部检查/诊断与阶段 5 的全范围验收。阶段 4 局部检查不能替代阶段 5，缺少前置阶段产物不得以先运行验收为由进入实施。阶段 5 按完整迁移项、规则与场景交叉核对，遗漏项回退补齐，遵循 [阶段门禁](stages.md)。

实现前列适用场景，至少覆盖本次核心操作链路与改变的契约；按风险增加正常、边界、失败、角色、返回、历史数据和容器场景。每项关联规则、条件/数据、动作、预期、方式、实际结果、环境/提交、证据。

状态使用「未执行、通过、失败、受阻、不适用」。不适用说明原因；失败写实际差异；受阻写缺失条件和补验步骤，不将已有截图或构建成功替代未执行场景。

| 待证明结论 | 证据与限制 |
| --- | --- |
| 关键数据转换 | 独立预期的函数测试或检查，不能代替真实接入 |
| 提交字段与状态闭环 | 真实操作、最终请求和响应后的状态 |
| 视觉和滚动 | 同视口/角色/数据/主题的渲染与连续操作 |
| 容器交互 | 目标容器或真机，桌面模拟仅辅助 |
| 工程可构建 | 对应版本、目录、环境与终态日志 |
| 发布/切换完成 | 对应环境实际版本、入口与运行证据，必须已授权 |

高影响参数、权限、状态及历史兼容选择能捕捉真实错误的验证。普通可逆低影响变化不机械新增测试；已有有效检查无需无理由重复。

## 视觉反馈与修改

先核对旧图/设计与新端状态可比，确认本次视觉目标是承接旧端还是采用指定新设计。按对象、当前表现、参照、期望、影响与修复验证记录问题，覆盖长短内容、最后一项可达、固定栏、安全区与返回。

已确认迁移要求内的实现偏差直接修复并复验。独立 UI 验收提出的未授权改进，完整列出全部意见，绑定报告版本，由用户勾选或回复 ID 后仅执行选中项；静态 HTML 勾选必须由用户将选择发送回会话，不自动执行。

## 排障

从最早的有效错误和执行阶段开始：安装 → 编译/资源 → 启动/代理 → 业务请求 → 容器。记录事实、候选原因、已排除项的依据、最小区分检查、修复层级和结果。

安装失败后的工具缺失可能是连锁结果；连接重置不自动证明某一方有错。同域接口成功只能支持该接口与条件，一次重试成功不能证明根因消失。环境故障先在环境层查证，不为通过构建绕过 Lint、扩大业务补丁或未授权改公共配置。

修复后复验原问题和实际受影响范围；保留失败与受阻的记录，不只报告最后一次成功。

# 范围与证据

## 启动基线

分别记录旧项目参照与目标项目实施的路径、分支、提交、已有未提交改动及其保护范围。没有 Git 时记录文件快照或取得时间，不能编造提交。读取两端适用项目指令与真实配置，不把旧端编码约定带入目标端。

启动卡覆盖：业务名称、用户最终动作、页面/角色/接口/容器、包含与排除范围、可修改目录、需求与截图、已确认限制、运行与验证环境。缺失信息保持待确认；存在明确授权时直接沿用。

只记录本次有关的框架、包管理器、锁文件、Node/CI 环境、构建脚本、公共能力和旧端运行条件。旧项目无法运行时，代码和历史截图可支持分析，但报告必须标明运行行为未验证。

## 证据分类

| 类型 | 能支持什么 | 使用方式 |
| --- | --- | --- |
| 观察事实 | 指定版本与环境下的代码、请求、日志或渲染现象 | 描述现状，判断是否属于承接要求 |
| 已确认规则 | 用户需求、有效文档或已核对且纳入范围的业务契约 | 关联实现与验收场景 |
| 待确认问题 | 来源冲突或缺乏依据的语义 | 标注受影响批次，询问最小必要问题 |
| 改进建议 | 可选择的结构或体验变化 | 说明代价，不冒充需求或已完成成果 |

关键项可用 F/R/S/T/E 编号交叉引用，不给每句话编号。依据写版本、文件、函数/组件和必要片段；行号只作辅助。请求与截图记录取得环境、数据状态和时间，脱敏凭证与个人信息。

证据相互冲突时展示具体差异，优先核对现行需求、真实接口及消费者。已授权且有依据的决定无需再确认；不能凭技术偏好决定新的业务含义。

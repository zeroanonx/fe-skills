# 完整迁移任务盘点

先展示本次全部迁移项，再逐项映射、规格化、实施。阶段 0 列范围和相关文件初表；阶段 1 完成全量盘点；阶段 2 补目标落点；阶段 3 将每项关联到正式任务与批次。阶段 4 前清单必须已完整落盘，禁止边写页面边猜剩余任务。

## 分类检查

| 类别 | 必须盘点的实际内容 |
| --- | --- |
| 页面与子视图 | 入口页、子页、弹窗/抽屉、公共或业务组件、职责与状态 |
| 路由与导航 | 菜单、路由参数、深链、刷新直达、跳转/返回、外部调用方 |
| 接口与请求 | 方法/地址、service/桥接入口、调用方、参数/默认值/转换、响应消费、异常反馈 |
| 函数与功能 | 事件函数、业务判断、校验、计算、格式化、选择/筛选/全选、提交、回填、取消、刷新与清理 |
| 状态与权限 | 角色可见/可操作范围、状态转换、共享 store/hooks、并发和防重、缓存/历史协议 |
| 样式与素材 | 页面容器、内容滚动、头底栏/安全区、字号/颜色/间距/对齐、组件样式、弹窗层级、图片/图标/字体/主题 |
| 工程与容器 | 业务依赖、配置影响、运行脚本、Bridge/WebView 能力、适用端和兼容风险 |

每类检查后记录有迁移项或“不适用及依据”；不能只列页面，也不能用“相关逻辑”“样式同旧版”覆盖大量未盘点内容。函数按独立业务职责盘点，注明关键函数名/调用链；自解释的局部变量不必单列任务，但它所服务的功能必须被覆盖。公共接口可列一次并关联所有消费方。

## 总表字段

| 迁移项 ID | 类别 | 页面/能力/接口/函数/样式项 | 旧端位置与稳定标识 | 行为/数据/状态 | 依赖/调用方 | 依据/未知 |
| --- | --- | --- | --- | --- | --- | --- |

阶段 1 为每项分配稳定 `M-001` 等 ID。阶段 2 增加业务不变项、工程适配、目标位置与处理决定。阶段 3 增加任务 ID、规则/场景 ID、批次和验证方式。阶段 4/5 增加实现状态、验收状态、实际文件/版本与证据；状态不得用一个完成勾合并。

总表可以按类别拆表，但保持完整索引与 ID。状态/未知项为空不等于默认确认；范围外项明确理由和授权依据，不能静默删掉或为了解锁实施而擅自排除。

## 覆盖检查

1. 从所有已确认入口递归检查路由、页面引用、事件、请求和公共依赖；按关键字段查生产方/消费方。
2. 对照截图/设计与源样式，核对每个主要区域、组件状态、长短内容及素材；源码与运行参照不一致时记录差异。
3. 在范围内的每个迁移项均有处理决定和至少一个正式任务；公共复用、明确替代或确认删除也记录决定和验证。
4. 每个正式任务必须能追溯到迁移项，每个应保持的规则必须有场景，每个批次列关联 ID。允许多对多，不为凑一一对应拆碎任务。
5. 新增/遗漏项先更新盘点、映射和规格，再进入实施；不以“基本都列了”通过门禁。

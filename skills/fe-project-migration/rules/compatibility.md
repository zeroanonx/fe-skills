# 按风险选择兼容检查

只加载实际存在的风险。没有共享状态或原生容器时不制造对应任务；存在却缺少环境时标记受阻并写明补验方式。

| 风险 | 需要查明 | 适合的验证 |
| --- | --- | --- |
| 共享状态/协议 | 生产方、转换、全部消费方、默认值、清理、账号切换 | 按操作链路验证消费者与最终请求 |
| 历史缓存/记录 | 存储键、版本、类型、缺字段、序列化、回填与失效规则 | 脱敏旧样本进入新端，核对回填与后续提交 |
| 多角色/状态 | 可见、可操作、请求范围、非法入口、状态变化 | 按实际角色矩阵与实体状态操作 |
| 路由/深链 | 旧入口使用方、参数、浏览器刷新、直达、返回与外部跳转 | 验证受支持入口和返回链路 |
| 原生/WebView | Bridge 请求、登录上下文、返回、键盘、滚动、安全区 | 指定容器或真机连续操作 |
| 多入口并行 | 旧新端数据可互通、缓存一致、重复事件与提交 | 同一数据经不同入口读取和修改 |

为每个风险记录需要保持的契约、目标适配、消费者、场景和证据。查集合完整性时区分分页/筛选结果与全集，按契约处理顺序、去重、ID 类型，不能未经依据排序或改类型。

默认值或缓存结构改变时，不擅自清空历史数据来掩盖不兼容。先核对使用范围，选择有依据的读取兼容、转换或失效策略，并验证用户结果。

目标端不再使用旧构建插件，并不能证明不受原生容器影响。浏览器验证不能替代 Bridge、原生返回或真机安全区。

## 切换与回退

用户要求并行接入或切换时，明确新旧入口、开关/路由归属、观测指标、回退触发条件及负责人，检查旧新写入是否兼容。方案可写入报告，实际发布、切流、停用和数据清理按明确授权执行。仅迁移模块时不擅自增加开关、删除旧代码或部署系统。

# 前端老项目迁移

承接已确认的业务语义与用户操作链路，使实现融入目标项目。旧代码提供现状证据，不能自动证明其中所有行为都是本次需求。

## 使用方式与范围

- `/fe-project-migration`；Codex 可用 `$fe-project-migration`，也可自然语言调用。
- **只读梳理**：用户要求熟悉、分析或盘点时，从阶段 0 开始，顺序完成约定分析范围，交付完整迁移盘点、业务地图与缺口，不改业务代码。
- **迁移方案**：用户要求方案或规格时，顺序完成阶段 0～3，交付完整迁移任务、映射、场景和批次，不执行阶段 4/5。
- **执行迁移**：用户要求迁移时，严格顺序完成阶段 0～5；每阶段检查产物与退出条件，阶段 0～3 未通过前禁止修改业务代码。已有授权不重复询问，但不能替代阶段门禁。

需要旧项目、目标项目位置和业务目标。沿用会话已有信息；先查仓库与资料，仍缺少时只询问影响工作的问题。目标项目不存在时，先明确创建项目的要求，不把现有项目迁移擅自扩大为搭建工程。默认前端范围，后端协议变化、旧系统停用与发布切流必须属于用户授权范围。

## 核心约束

1. 记录两端分支、提交、工作区与适用项目规则，保护既有改动；默认只写目标项目及指定交付目录。
2. 区分观察事实、已确认规则、待确认问题、改进建议。关键结论附提交、文件及函数/组件等依据。
3. 分开列业务不变项与工程适配项；权限、状态、默认值、提交参数和返回语义不能因技术栈变化而悄然改变。
4. 先列全本次迁移项，再逐项映射、写规格、分批实现。任何批次都不能绕过阶段 0～3；前期有歧义时可继续独立分析，不能提前编码。阶段 4 出现新歧义时只暂停依赖批次，按阶段规则回退补齐依据。
5. 小批次按可验收的业务动作划分；实现、场景验证、构建、发布分别记录，不互相替代。

## 严格阶段流程

首先读取 [阶段顺序与门禁](rules/stages.md) 和 [完整迁移任务盘点](rules/task-inventory.md)。必须按以下顺序执行，禁止合并阶段、先实现后补文档，或以一个已知页面代替完整盘点。

| 阶段 | 必须产出与退出条件 | 细则 |
| --- | --- | --- |
| 0：建立可以复核的基线 | 两端版本、工作区、范围、相关文件初表、环境与参照；参照及保护边界明确 | [基线](rules/baseline.md) |
| 1：把老代码读成业务地图 | 完整链路、页面/接口/函数功能/样式等迁移盘点、依据与未知项；本次范围盘点闭合 | [业务地图](rules/business-map.md)、[盘点](rules/task-inventory.md) |
| 2：确定业务不变项与工程适配项 | 逐项旧新对照、保留契约、适配方案、目标落点与影响；所有迁移项均有处理决定 | [工程映射](rules/target-mapping.md) |
| 3：把规格写到可以执行和验收 | 全部任务、规则、场景、依赖、批次及修改范围；关键歧义已解决，任务覆盖可检查 | [规格](rules/specification.md) |
| 4：批次实现与范围检查 | 按阶段 3 批次实施，逐批 diff、检查、实际结果；全部批次有明确实现终态 | [批次](rules/specification.md)、[诊断](rules/verification.md) |
| 5：验收，让规则、场景与证据能够对应 | 全范围场景验证与真实证据、缺口和结论；通过需约定适用场景全部闭合 | [验收](rules/verification.md)、[交付](rules/delivery.md) |

每阶段记录未开始/进行中/通过/未通过/受阻、产物路径、依据和退出检查。阶段状态通过后才进入下一阶段；已有材料必须核对当前版本与完整性后才能复用，不能直接称为“已完成”而跳过检查。只读/方案模式按目标阶段结束，后续保持未执行。

有共享状态、历史数据、角色权限、原生容器或并行入口时，按 [兼容性检查](rules/compatibility.md) 纳入阶段 1 盘点、阶段 2 映射、阶段 3 场景与阶段 5 验证。只可减少不适用细项并写明依据，六个阶段及完整盘点不可省略。

## 产出

默认写入 `{目标项目}/fe-spec/project-migration/{模块}/{run-id}/`，`run-id` 使用 `YYYYMMDD-HHmmss`，冲突时追加序号；用户指定路径优先。

- `migration.md`、`migration.html`：同轮次同内容的迁移报告，包含当前模式、六阶段状态、完整迁移任务清单、基线、地图、映射、规则、批次、验收结果与缺口。阶段 4 前必须已生成阶段 0～3 产物；报告随阶段更新，不能等实现后补写全部任务。
- 代码、必要测试：只在执行迁移模式、已授权范围内生成。
- `evidence/`：真实截图、日志与请求记录，按需保存并脱敏；未能取得的证据写明缺口。
- `handoff.md`：仅在跨会话、未完成或需要接手时生成，记录决策、版本、有效证据、受阻项与下一步。

规格优先沿用项目已有 OpenSpec 或文档结构，不安装或强制指定工具版本。报告链接这些规格，不维护两套冲突规则。参考 [Markdown 模板](templates/migration.md) 与 [HTML 模板](templates/migration.html)，保留六阶段状态与完整迁移任务清单，不适用细项说明原因，替换全部占位符。

## 与其他技能协作

可用时，编码细则使用 `fe-ai-coding`，视觉基准使用 `fe-design-analysis`，实际页面验收使用 `fe-ui-verification`。这些技能不是安装前提；缺失时按本技能细则完成工作。独立 UI 验收提出的新改进意见，先完整列出再由用户选择；用户已明确授权的迁移修复继续执行，不为调用其他技能重复询问同一授权。

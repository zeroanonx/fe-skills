# 浏览器与设计证据

## 工具选择

使用用户指定且可用的浏览器；否则选当前环境具备导航、截图、交互能力的浏览器工具，如内置浏览器、Browser 或 Playwright。工具名和参数以当前说明为准，不预设 Cursor 专有方法。

Figma 或 Pencil 设计使用对应的可用工具，并遵守其前置技能要求；静态图直接查看原图。设计或页面不可访问时记录阻碍，已有部分可继续检查。安装新工具或修改登录配置不属于默认验收步骤。

## 可比条件

- 记录 URL、浏览器、视口 CSS 宽高、DPR、缩放、主题、语言、角色和数据状态；未知项明确标出
- 对齐画板与页面区域、滚动位置、弹层/Tab 状态；不把不同视口或状态产生的差异直接判为缺陷
- 等待目标区域的数据、字体和图片稳定，记录尚未完成的加载；不只依赖固定等待秒数
- 长页面按区域取证并保留滚动位置；检查固定头部、底部、右侧和遮罩，不只看首屏
- 动态数据、时间和动画造成的不可比区域单独说明；用户要求响应式时检查约定视口，没有对应设计的视口只验证可用性

## 截图与元素

截图用于视觉确认，元素边界与计算样式用于解释差异。可访问性树通常不含真实坐标或样式；如需尺寸/颜色，使用工具实际支持的边界测量或 computed style，不把源码 CSS 值当渲染结果。

设计节点与网页元素不必一一对应；以可见分组、叠放、交互和尺寸为判断对象。

证据名称可用 `design-A.png`、`actual-A-before.png`、`actual-A-after.png`，多视口/状态加后缀。保留原始尺寸；若用裁切、叠图或像素差，说明处理条件与测量口径，不能仅凭抗锯齿差异判错。只引用本次真实保存的文件或可追溯工具证据。

## 交互复验

根据验收范围实际触发 hover、focus、active、disabled、弹窗、Tab、空状态等，再截图；触发失败即记未验证。涉及真实提交或删除时遵守用户授权和环境约束，优先使用已有测试数据。

修复后用相同页面、视口和数据复验，追加证据与时间。页面版本无法确认时说明限制，不将旧截图当新结果。

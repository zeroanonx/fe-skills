# 修改意见、勾选与执行

先完成约定范围的验收，整理**全部修改意见**，生成并打开 HTML/Markdown 报告，再询问是否修改及选择哪些项。不要边检查边直接改业务代码，也不要只展示高优先级意见后省略其他项。

## 意见内容

每项使用稳定 ID（如 UI-001），包括区域/状态、问题与证据、期望效果、具体修改建议、影响范围、优先级、风险/依赖和预期验证方式。定位到文件后可附路径；未定位时说明，不编造位置。

意见与问题 ID 对应，一项多个互斥方案需明确选择方案。前置依赖、公共组件影响与需要补齐的素材应在选择前说明。全部意见包括本次 P0/P1/P2；尚无法给出方案的发现列为待确认项。

## 意见版本与有效范围

每份清单绑定 report.html 的完整路径、run-id、报告更新时间，以及当前设计/页面版本（无法读取版本时注明）。ID 在同轮次稳定，不重新编号或复用已删除 ID。

用户选择后，先确认选择对应本次报告、ID 存在且未关闭、方案没有变化。页面代码或设计已变更、报告已新增/替换方案时，先重新核对受影响项并展示差异；原选择仅适用于方案和影响范围未变化的项。

互斥方案只能选其一；依赖项未选中时说明依赖并请用户取舍，不能默认追加到执行范围。用户回复含不明确或不存在的 ID 时，先确认这些项，可继续处理其余已明确且独立的所选项。

## 用户选择

- HTML 报告提供逐项 checkbox，**默认均不勾选**；Markdown 提供同 ID 的任务列表。
- **没有待执行修改意见**时直接交付报告与结论，不询问是否修改。
- 完整列表展示后询问「是否修改？请选择要执行的意见」，允许多选、全部执行或仅保留报告。
- 交互工具支持多选时使用真实多选问询并接收返回；不支持时让用户勾选报告并将生成的所选 ID 指令发送到当前对话，或直接回复要执行的 ID。
- 静态 HTML 的 checkbox 只记录本地选择。用户点击生成指令后仍须将指令发回对话；报告不能自行启动 Agent，也不能把浏览器里的临时勾选当成已经收到的用户授权。
- 用户在完整清单展示后明确说「全部修改」「修改 UI-001、UI-003」即可执行，无需再次确认。选择为空或用户未回复时只交付报告，保持业务代码未修改。
- 首次仅说「检查并修复」仍先交付完整修改意见并请求选择；用户已在当前清单上明确选择的项不重复询问。

## 按所选项修改

在报告记录所选 ID 和用户决定。只处理所选项，按优先级与依赖顺序执行；未选项保留为「未选择，待修复」，不是已确认例外，也不能影响报告真实性。

公共组件或依赖改动会扩大到未选择范围时，先说明具体新增影响并等待取舍；可执行互不依赖的所选项。执行中发现新问题则补充完整清单并让用户选择新增项，不默认顺带修复。

修改后运行相关代码检查，以原视口/状态重新比对页面；状态更新为已修复待复验、复验通过或复验未通过，同步 HTML/MD，再次打开本轮 HTML。

## 交付

说明所选项的修改和复验结果、未选择项数量及未验证范围。整体存在未解决差异时仍为未通过，不因为所选项已修完就声称整页通过。

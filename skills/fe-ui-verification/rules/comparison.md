# 比对维度与问题分级

## 按区域检查

从上到下、从左到右、从外到里检查。四个基础维度均要覆盖，但维度不是严重级别。

| 维度 | 检查内容 |
| --- | --- |
| 布局 | 容器范围、排列方向、列数、间距、比例、对齐、固定/吸附区域、滚动和按钮尺寸 |
| 层级 | 视觉分组、先后顺序、弹层/遮罩叠放；无需强求 DOM 与设计图层一致 |
| 文字 | 标题、说明、Tab、按钮、占位和提示的完整性、内容、换行/截断 |
| 图片 | 素材是否正确、图片/图标缺失、尺寸、裁切、圆角、占位与多图布局 |
| 样式 | 字体、字重、行高、颜色和透明度、边框、圆角、阴影及主题 |
| 状态 | 本次约定的 hover/focus/active/disabled/loading/empty/error、弹层、响应式 |

每项标「通过 / 存在差异 / 未验证 / 不适用」，未验证与不适用都需要理由。

## 优先级

| 等级 | 判定 | 示例 |
| --- | --- | --- |
| P0 | 阻塞验收或核心使用 | 核心操作被遮挡无法点击、主内容不可见、关键操作含义错误 |
| P1 | 明显偏离设计，应修复 | 主要区域错位、重要素材缺失、文字严重截断、指定视口布局失效 |
| P2 | 局部细节，可排期优化 | 轻微间距、非关键图标偏移、局部圆角差异 |

依据用户影响和约定标准分级，不能把任意错字、图片或布局差异一律标为 P0。同等级内按区域顺序排列。容差由用户或项目标准决定，无标准时记录实际差值，不编造统一阈值。

## 问题证据与关闭

每条包含稳定 ID、区域/状态、复现步骤、设计期望及来源、实测与截图、影响、等级、建议和当前状态。原因尚未证实时标「可能原因」，不要把猜测作为结论。

状态使用「待修复 / 已修复待复验 / 复验通过 / 复验未通过 / 已确认例外」。例外需记录用户或项目依据，不能自行豁免。分析清单遗漏可归因并建议补充，不自动修改共享 Skill。

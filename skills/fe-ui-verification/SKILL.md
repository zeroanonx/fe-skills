# 前端 UI 验收

以实际运行页面与设计稿的比对为依据。源码、构建成功或分析清单只能辅助定位，不能代替页面证据。

## 何时使用

- 实现后检查设计还原度、记录视觉差异，或修复后的复验
- 触发：`/fe-ui-verification`；Codex 可用 `$fe-ui-verification`，也可自然语言调用
- 只有设计稿、没有实现页面时使用 `fe-design-analysis`；代码质量审查使用 `fe-code-review`

## 输入与范围

从上下文获取目标项目、页面 URL、设计来源/版本、目标视口与待验状态。可附 `fe-design-analysis` 的 `analysis.md`，没有清单也能直接对照设计验收。

- 先检查并完整列出修改意见、生成并打开报告，再询问是否修改及选择哪些项；收到用户对本次清单的选择后才改业务代码。选择规则见 [修改意见与勾选](rules/workflow-modification-selection.md)
- 缺少页面或设计时，报告「受阻/未验证」并说明缺什么；可完成已具备证据的区域，不虚构通过结论
- 没有设计基准时可以记录页面自身的可见问题，但不能宣称设计还原验收通过
- 不把静态截图里未展示的状态推断为设计要求；记录为待确认或另行交互检查

## 产出目录

默认写入目标项目，用户指定路径时遵从用户：

```text
fe-spec/ui-verification/{页面或模块名}/{run-id}/
├── report.html    # 可视报告，交付时主动打开
├── report.md       # 环境、覆盖范围、差异、结论和复验记录
└── screenshot/     # 设计、实际页面、修复前后证据
```

`run-id` 使用 `YYYYMMDD-HHmmss`，冲突加 `-2` 等后缀；模块名不得包含路径分隔符。同次复验更新问题状态并追加记录，保留旧证据；新的验收轮次新建目录。不在 Skill 安装目录写报告。证据无法保存时记录工具证据引用及限制，不生成虚假文件链接。

## 工作流程

1. **锁定比对条件**：读取 [rules/tools.md](rules/tools.md)，记录 URL、设计版本、浏览器、视口、缩放、DPR、主题、账号角色及数据状态；无需记录账号凭据。
2. **获取实际证据**：打开目标页面，等待字体、图片、数据稳定，截取整体和关键区域；取得设计同区域截图或节点属性。页面未正常加载时先记录阻碍，不能当成设计差异。
3. **逐区检查**：读取 [rules/comparison.md](rules/comparison.md)，从上到下、从左到右、从外到里检查布局、层级、文字、图片，再看样式和指定交互状态。每条差异带期望、实测、影响及证据。
4. **生成并打开报告**：读取 [问题清单规则](rules/workflow-problem-list.md)，使用 [Markdown 模板](template/report.md) 与 [HTML 模板](template/report.html) 生成双格式报告。按实际影响定级、记录覆盖和限制，列出全部修改意见与默认未选的勾选项，主动打开本次 HTML；无问题也交付报告。
5. **询问与选择**：有待执行意见时按 [选择流程](rules/workflow-modification-selection.md) 展示全部意见并询问，等待用户多选 ID、全部执行或仅保留报告；没有意见则直接交付。未选择前不修改业务代码。
6. **执行所选项与复验**：核实报告版本和所选 ID，按依赖和优先级只修改所选项，重新打开页面取证；未复验标「已修复待复验」。同步 HTML/Markdown 的选择、问题状态和复验记录，并重新打开本次 HTML。

## 结论规则

- **通过**：约定范围均已验证，没有未解决差异；已确认的设计例外单独列出
- **未通过**：仍有未解决差异；若还有未验证项一并说明
- **部分验证**：只完成部分范围，暂未发现差异不代表整体通过
- **受阻**：缺少必要工具、访问权限或基准，无法开始有效比对

不输出无依据的「还原度 95%」；需要量化时只提供有明确分母的覆盖率（已验证项/计划项），不冒充视觉相似度。

## 交付要求

- 主动打开本次 `report.html` 并检查渲染，输出 HTML 与 `report.md` 的绝对路径链接、结论、全部修改意见、待选择/所选项、各等级未关闭数量和未验证范围
- 图像及元素属性均应来自本次真实读取；DOM/可访问性快照不等于尺寸、颜色等计算样式
- 分析清单遗漏可写入报告末尾，必要时同步本次任务文档；修改共享 Skill 需要用户明确要求
- `fe-design-analysis` 提供视觉基准，`fe-ai-coding` 约束修复代码；按需配合，不依赖固定安装路径
